02Processo

Como eu trabalho.

Quatro etapas que se repetem em qualquer entrega — do chamado no suporte ao projeto que vai para produção.

01 / 04

  1. Entender a operação

    Ambientes ativos, ERP, bancos corporativos e integrações que não podem cair. Antes de mudar qualquer coisa, mapeio o que está rodando e quem depende daquilo.

    Na prática Sankhya ERP, SAP GUI, GLPI e bancos Oracle em produção.

  2. Diagnosticar com dados

    Sintomas parecidos podem ter causas completamente diferentes. Consolido eventos e consultas até o problema virar uma lista de causas — cada uma com a sua correção.

    Na prática O Seslock Holmes separa bounce por subtipo: endereço, MX ou DMARC.

  3. Automatizar o que se repete

    Se a tarefa se repete, ela vira workflow, script agendado ou integração por API — de preferência sem uma máquina ligada só para isso.

    Na prática Quatro bots migrados de n8n self-hosted para GitHub Actions.

  4. Medir o resultado

    Entrega boa é a que aparece no indicador — bounce, tempo de rotina, chamado resolvido. Se o número não mexeu, o trabalho não acabou.

    Na prática Bounce de 11,6% para 0,8% em um provedor; 50% menos trabalho manual.
